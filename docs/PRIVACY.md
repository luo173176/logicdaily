# 隐私说明

这份文档回答三个问题：**数据存在哪里**、**什么情况下会离开你的设备**、**怎么把它带走或删掉**。
代码层面的实现细节见 [ARCHITECTURE.md](ARCHITECTURE.md) 与 [AI_INTEGRATION.md](AI_INTEGRATION.md)。

## 1. 默认情况下：数据不出设备

LogicDaily 是本地优先应用。未配置 AI、未部署后端、也没有开启本机直连时，**不存在任何形式的数据上行**：

- 所有记录写进浏览器 IndexedDB（数据库名 `logicdaily`）。
- 判分、错因归类、复习调度、掌握度、训练报告全部在浏览器里用纯函数计算。
- 服务端只有两个接口（`/api/ai/status`、`/api/ai/analyze`），未配置模型凭据时它们只返回「未启用」。
- 没有埋点、没有统计 SDK、没有第三方脚本、没有广告 SDK。可以自行检查 `app/layout.tsx` 与 `package.json` 依赖清单。

**用 APK 时基本成立，但要注意三点差别**：（1）它是 WebView 里的 IndexedDB，与浏览器那份是**两个独立存储域**，互不继承，也不是同步关系；（2）包里根本没有服务端，所以**服务端代理那条 AI 通路在 App 内不可用**；但 App 内可以开启**本机直连**（见第 3 节），开启之后应用代码会主动向你在设置里填的那个地址发请求 —— 这是一条真实的数据外发路径，不是「少了一条」；（3）APK 打进本地资源后从 `https://localhost` 加载（`capacitor.config.ts` 不设 `server.url`），清单只声明 `android.permission.INTERNET`：**不开启直连时应用不会主动发起任何网络请求**（`lib/ai/client.ts` 请求的本站 `/api/ai/*` 在包内不存在，只会得到一条降级说明），开启直连后 INTERNET 权限就真的被用于连外部服务商。第（3）点是这样设计的，但**未在真机上用抓包验证过**。

## 2. 存了哪些字段

| 类别                      | 内容                                                                                     | 敏感度高低的直观说明                       |
| ------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------ |
| 作答记录 `attempts`       | 题目 id 与版本、选项/文本、得分、用时、信心、你写的推理过程、错误类型、归因              | 中等：推理文字会暴露你的思考方式           |
| 思考日志 `journals`       | 真实问题的背景、事实、假设、结论、替代解释、不确定点、验证动作、复盘结果、标签、证据清单 | **最高**：这是你生活里没想清楚的问题本身   |
| 复习与掌握度              | 每题的调度状态、每个知识点的 EWMA 掌握度                                                 | 低                                         |
| 计划与进度                | 每天生成什么、完成了什么                                                                 | 低                                         |
| 设置                      | 每日时长、题型偏好、休息日、时区、主题、提醒时间、AI 参数（含模式与你填的 Base URL）     | 低；**设置记录里不含任何密钥**             |
| AI 密钥（仅直连模式）     | 你填的服务商 API Key，明文存在这台设备的 `localStorage`                                  | **高**：它等价于你能花钱、能读你账户的凭据 |
| AI 结果 `aiAnalyses`      | 结构化结论 + 提示词版本；`retainedInputSummary` 恒为 `null`                              | 中：不回存发送出去的原文                   |
| AI 用量 `aiUsage`         | 模型名、token 数、耗时、状态                                                             | 低                                         |
| 题目复核 `exerciseIssues` | 你标记「题目有歧义」的题目 id 与你的选择                                                 | 低                                         |

**没有采集的**：姓名、邮箱、电话、精确地理位置、通讯录、设备指纹、跨站标识符。访客身份是固定字符串 `local`，不是可追踪 ID。

## 3. 什么情况下数据会离开设备

只有一种情形：**你主动使用 AI 思维教练**。它有两条形成的通路，去向不同，请分清：

- **服务端代理**（默认）：你 → 你自己的部署 `/api/ai/analyze` → 部署者在服务器上配的那家服务商。密钥不经过你的设备。
- **本机直连**（需在这台设备上显式开启）：你 → **直接**到你在设置里填的服务商地址。不经过任何服务器，部署者看不到也无法审计。

| 你做的事                                           | 会发送                                         | 不会发送                     |
| -------------------------------------------------- | ---------------------------------------------- | ---------------------------- |
| 答题后点「请教练追问」                             | 该题的结构化信息 + 你填写的推理文字 + 你的选择 | 思考日志、其他题目、历史作答 |
| 在日志编辑器勾选「允许把这篇送去 AI 分析」后点分析 | **这一篇**日志的向导字段与证据清单             | 未勾选的其他日志、作答记录   |
| 材料分析页粘贴一段文字                             | 你粘贴的文本（≤ 允许长度）                     | 任何本地记录                 |
| 周度小结                                           | 本地统计聚合数字                               | 逐条作答原文                 |
| 「测试连接」                                       | 一个 `ping` 任务                               | 任何用户数据                 |

未勾选 `aiConsent` 时，日志正文不会进入 AI 请求体——这个开关在编辑器里是显式复选框，默认不勾选，勾选时界面上写明了会发送什么。
两种模式共用同一套入参校验，所以**不存在「直连时这个确认开关被绕过」的情况**。

第三方服务商拿到什么，取决于哪条通路：代理模式由部署者的 `AI_BASE_URL` 决定，直连模式由你自己填的地址决定；
两种模式下本仓库都不向任何第三方转发数据，也不额外采集任何内容。直连时请求里唯一多出来的东西是你自己的
`Authorization` 头，它只发给你的服务商，且不会出现在导出备份里。

## 4. 日志与可观测性

服务端只在结构化日志里记录元数据：

```
{ evt: 'ai_call', task, model, ms, tokens, status }
```

明确**不记录**：API Key、`Authorization` 头、完整请求正文、思考日志原文、作答推理文字。URL 在记录前经 `redactUrl()` 处理。
限流使用内存计数，进程重启即清空；不保留历史 IP 名单。

**直连模式下没有服务端日志可言**：请求不经过任何服务器，因此这次调用在服务器侧完全不可见。本机仍然会写一条
`aiUsage` 元数据（模型名、耗时、token 数、状态），用于「今天已调用几次」这类自己的统计——它同样不含密钥与原文。

## 5. 多用户隔离

- 每条用户数据都带 `profileId`，所有查询按 `profileId` 过滤；访客固定为 `local`。
- Dexie 复合索引 `[profileId+dateKey]`、`[profileId+exerciseId]` 保证隔离在索引层就生效。
- `tests/integration/local-store.test.ts` 与训练流程测试里有专门的「不同 profile 互不可见」断言。
- 云端模式（Phase 3）的表结构已按 Supabase RLS 写好策略：每个用户只能读写 `owner_id = auth.uid()` 的行，共享题库表对客户端只读。该 SQL 已在本地 Postgres 上验证过 RLS 隔离，但**应用尚未接入**。

## 6. 备份文件里有什么

「我的 → 导出备份」生成一个 JSON 文件，包含你的全部本地数据（题目本身不含在内，题目由内容包提供）。

- 文件带 `app`、`version`、`generatedAt` 标识，导入时校验，非本应用或结构不符会被拒绝。
- 导入设置时会**主动剥离** `apiKey` / `key` / `token` 字段：即使你手工往备份里塞了密钥，也不会被写进应用设置。
- 直连模式的密钥**根本不在备份里**——它存在 `localStorage`，而备份导出的是 IndexedDB 的设置记录。这是结构性保证，不是「导出时记得删掉」。端到端与包内验证各有一条用例真的导出一次文件并断言搜不到那串 Key。
- 备份文件是明文。**请把它当作包含你私人日记的文件来对待**：不要上传到公开网盘、不要提交进仓库、不要发给别人。

## 7. 删除数据

| 操作                | 位置                   | 效果                                                                                                             |
| ------------------- | ---------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 删除单篇日志        | 日志编辑器             | 软删除（列表与统计立即消失，可彻底删除）                                                                         |
| 彻底删除单篇日志    | 日志编辑器 → 彻底删除  | 从 IndexedDB 物理移除                                                                                            |
| 清除全部本地数据    | 我的 → 数据管理 → 清除 | 清空所有记录（可选保留题库），**同时删除这台设备上保存的 AI 密钥**，不可撤销，操作前有确认                       |
| 卸载/清除浏览器数据 | 浏览器设置             | 同上，浏览器直接抹掉整个 IndexedDB                                                                               |
| 已发送给模型的內容  | —                      | 本应用无法撤回。需要联系处理这次请求的服务商（代理模式是部署者配的那家，直连模式是你自己填的那家），按其政策处理 |

## 8. 提醒与通知

- 提醒决策在本地完成（`lib/services/reminders.ts`），不需要服务器。
- 若你授权系统通知，应用可以弹出本地通知。**没有实现服务端推送**（无 `PushSubscription`、无推送服务器），因此关闭浏览器后不会有提醒。这一点在设置页里也写明了，没有夸大 PWA 的能力。

## 9. 儿童与未成年人

本应用不采集身份信息、不含社交功能、不投放广告。但它会记录用户真实生活中的困惑与判断，其中可能出现他人姓名或可识别信息——这些内容只存在用户自己的设备上。若用于课堂教学，建议由学生自己在个人设备使用，或统一使用「清除本地数据」流程。

## 10. 安全问题的披露方式

发现可能泄露用户数据的问题（例如 SSRF 绕过、密钥泄漏到前端、备份文件被误上传），请按 [SECURITY.md](SECURITY.md) 私报，不要公开提 Issue。

## 11. 如果你是自己部署的

需要向用户说明的三件事：

1. 你配置了哪家模型服务商（`AI_BASE_URL` / `AI_MODEL`），用户的提问内容会被那家服务商处理。
2. 你的服务端日志保留策略（本应用默认只写元数据，但宿主平台的访问日志可能记录 IP 与 URL）。
3. 是否启用了云端账户与同步（当前版本没有）。
4. 用户还可以在自己的设备上开启**本机直连**，此时内容不经过你的服务器、直接发往用户填的服务商。你看不到这些调用，也无法从服务端关闭它；请在你的隐私政策里单独说明这一条。
